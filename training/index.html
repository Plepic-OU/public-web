Watch: live

  • Claude Code and the agentic loopThe cycle an agent repeats until the task is done: read the context, call a tool, check the result.: context, skills, subagents, tools (CLI or MCPModel Context Protocol. The standard way to connect an agent to outside tools and data, such as your issue tracker or database.), permissions, plans and pricing
  • Hooks: observe every tool call, block the dangerous ones

Build: your work

  • Set up Claude Code on your own project, or vibe code one, then turn /init’s draft into AGENTS.mdA Markdown file in your repo that coding agents read at the start of every session: your commands, conventions and rules. /init drafts it as CLAUDE.md; you turn that into AGENTS.md.
  • Two hooks: one logs every tool call, the other blocks a secret file; your partner tries to bypass it

Watch: live

  • Context and caching, then maps: an agent-friendly repo, the C4 modelA way to draw software architecture at four zoom levels: system context, containers, components and code., generate don’t draw
  • Spec-driven development, runnable scenarios, the testing pyramid and subagentsHelper agents that the main agent starts for one task, each with a fresh context. Typical jobs: review, validation, search.

Build: your work

  • Build a skill that generates C4 and database maps, linked from AGENTS.md
  • Write spec-interview and spec-review skills, then review your spec with parallel reviewer subagents
  • Pick the model and effort for each reviewer

Watch: live

  • Verification loops: scripts first, then AI reviewing AI, then a human
  • Loop engineering: agent, verification, event-driven and improvement loops; goals and gates

Build: your work

  • Build your spec in stages: Claude stops after each, a reviewer skill checks it, you decide, then /code-review
  • Build a gate: your tests plus one metric, a baseline and an exit code; break it on purpose
  • Run the full loop: Claude loops until a test passes, then /goal improves your metric

Watch: live

  • Introspection and observability: session logs, /insights, OTEL metrics
  • Agent-native architecture, and proactive loops that run without you: log analysis, slow-query triage, payment matching

Build: your work

  • Complete 2–5 GitHub issues in parallel, each agent in its own worktreeA git feature that checks out several branches side by side, so each agent works in its own copy of the repo.

Capstone projects

What participants built in days 5 and 6

Most came from their own daily work; some were personal. Pick a problem.

  • Began adding tests to a 164,000-line application that had none, riskiest business logic first.
  • Built a review gate and a verify gate for AI-written code: the verify gate breaks the code on purpose to see whether the tests notice.
  • Made a read-only catalog of thousands of automated tests across repositories, readable by managers as well as engineers.
  • Wrote browser tests for two new country versions of a product. Claude writes, runs and fixes each test until it passes three times in a row.
  • Wrote runnable usage examples for a library that had none; they double as regression tests.
  • Planned a database migration of a business-critical service, with old and new running side by side to compare results.
  • Rewrote an internal admin app from an old Java web framework to React and Spring Boot, with generated API clients and new tests.
  • Removed a ten-year-old layer around the database in stages small enough to review, and proved that the generated SQL stayed the same.
  • Migrated an AngularJS front end to modern Angular one piece at a time, with end-to-end tests as the safety net.
  • Upgraded a portal stuck on Java 1.6: dependencies, getting it running, end-to-end tests, dead code.
  • Replaced an abandoned modeling tool with a standalone app, using about 100 existing models as tests that the generated code stays identical.
  • Profiled a backend service and found a library compiling a regular expression on every event. The fix halved CPU use.
  • Found out why a web console kept open all day slows down, using heap snapshots, and ranked the fixes.
  • Patched an open-source game launcher for touch on a Raspberry Pi: 11 patches, and one fix cut world loading from 2 minutes to about 5 seconds.
  • Fixed a years-old bug in an open-source device library, then pointed a camera at the device so Claude could check the fix itself.
  • Mapped a large multi-repo platform: C4 diagrams down to components, data flows, database schemas and 250 findings, with an agent that checks every document against the code.
  • Turned 100 pages of system documentation into a browsable model that links requirements to processes, use cases and code.
  • Moved a company’s scattered know-how into git-versioned markdown, served over MCP. Agents propose updates as diffs for a human to accept.
  • Turned a ticket number into ready context for Claude Code: the related repositories, wiki pages and skills.
  • Kept a C4 map up to date with a skill, and added a brainstorming skill that turns business input into analysis and task drafts.
  • Built a pipeline of skills that extracts a knowledge base from slides and notes, with a validator on every step.
  • Built a read-only MCP server with pseudonymized data, so customers’ agents can ask how a complex system is set up.
  • Added write operations and an MCP server to a product’s API, with confirm dialogs, dry runs and an agent whose job was to break it.
  • Built a no-code REST service builder where an assistant on a self-hosted model writes the SQL and configures the endpoint.
  • Built a support bot that answers in five languages from a knowledge base and hands uncertain cases to a human.
  • Upload a PDF invoice, the model reads it, and the user checks a prefilled form.
  • Classify incoming email: rules first, AI for the rest, a human confirms.
  • Replace a monthly report assembled by hand from many Excel and PDF formats with one pipeline.
  • Check a codebase against a customer’s non-functional requirements with a local model.
  • Train a small multilingual model to detect prompt injection, and compare it with an open model.
  • Rules and skills strict enough to enforce company policies, then a feature built from the spec in parallel worktrees.
  • A kanban board where agents on several machines hand tasks to each other over MCP.
  • Design inside the spec flow: UI prototypes kept in sync with the code and the design system.
  • A closed build loop on an ERP platform: compile, read the errors, fix, run the best-practice checker. Deploys only with human approval.
  • A loop for a large monolith where every finished task leaves lessons for the next one.
  • Slash commands, hooks and issue-tracker connections for a team, then real work done with them.
  • A sandboxed agent environment identical to the developer’s own, without exposing sensitive dependencies.
  • A shared UI component library, a devtools plugin for debugging analytics requests, a status page for a fleet of tablets.
  • An operations and testing console that replaces several internal tools and direct database access.
  • A test management plugin for the team’s issue tracker, replacing spreadsheets.
  • A staffing app built from the spreadsheet used to put together CVs for tenders.
  • An API tester for a legacy backend, so front-end developers don’t have to wait.
  • A configuration builder that keeps settings consistent across services.
  • A route planner for inspection shifts with time windows.
  • A simulator for the device behind a serial-port diagnostics app, so the app can be tested without hardware.
  • Smart-home apps: a fast replacement for a hub’s slow app, with voice commands, and a home server rebuilt from an existing system’s API.
  • A murder-mystery game where Claude plays every suspect and only the killer lies.
  • A tabletop role-playing encounter builder: the model picks the monsters, deterministic tools do the maths.
  • A daily crawler for car-sale sites, a terminal app for a record collection, an investment tracker, open-source accounting software for a family member.
  • An arcade game, a 2D platformer, a 3D throwing game.
  • A browser extension that merges two school portals for parents with several children.
  • A database manager built by agents in overnight loops.
